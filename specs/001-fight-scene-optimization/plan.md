# Implementation Plan: 战斗场景全章优化

**Branch**: `001-fight-scene-optimization` | **Date**: 2026-05-29 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-fight-scene-optimization/spec.md`

## Summary

对全部 84 章正文中的战斗场景进行系统性回炉优化。基于 `novel/研究/战斗场景参考.md`（11 章参考手册 + 10 项自查清单），通过「扫描诊断→逐章回炉→一致性修复→双线区分→终审」五阶段流程，将全部战斗的平均自查通过率从预估 ≤5/10 提升至 ≥8/10。

## Technical Context

**Language/Version**: 中文网络小说，Markdown 格式，每章一个 `.md` 文件

**Primary Dependencies**:
- `novel/研究/战斗场景参考.md` — 战斗写作权威参考（硬约束：核心原则+自查清单；强指导：四段结构/三要素/辨识度/多感官；弹性：句式/视角/笑点/对标技法）
- `.claude/rules/story-format.md` — 格式规则（段落 ≤60 字、段落间无空行、对话无标签）
- `.claude/rules/story-colloquial.md` — 口语化规则（对话/独白必须自然）

**Storage**: 文件系统 — `novel/正文/第XXX章_标题.md`（84 个文件），Git 版本控制

**Testing**: 10 项自查清单逐场自评，AI 自主判断通过/不通过

**Target Platform**: 小说成稿，最终阅读载体为网文平台

**Project Type**: 内容优化 / 写作质量提升

**Quality Targets**:
- 全部战斗平均自查通过率 ≥ 8/10
- 核心战斗（首次新敌人/BOSS战/有情感弧线）≥ 10/10
- 一致性校验 0 个 S1/S2 冲突
- 例外比例 ≤ 15%

**Constraints**:
- 不改剧情走向、章节结构、角色关系
- 非战斗核心叙事不动
- 战斗相关过渡文字可自由调整
- 遵守格式规则（60字段落、无空行、无对话标签）

**Scale/Scope**: 84 章，预估 25-35 章含战斗段落（~30-60 场战斗），需修改文件 20-35 个

## 执行阶段

### Phase 1: 扫描与诊断（US1）

**目标**: 产出完整战斗场景索引表 + 质量初评矩阵

**步骤**:
1. **并行扫描**：5 个 agent 各负责 ~17 章
   - Agent A: 第001-017章
   - Agent B: 第018-034章
   - Agent C: 第035-051章
   - Agent D: 第052-068章
   - Agent E: 第069-084章
2. **每章扫描**：grep 战斗关键词 → Read 确认段落实体 → 提取行号/字数/角色/敌人/类型
3. **初评**：按 10 项自查清单逐场打 ✓/⚠/✗
4. **合并**：主线程汇总 5 份 agent 产出 → 统一 `combat-index.md` + `quality-matrix.md`
5. **分类排序**：标注回炉优先级（重度/中度/轻度/免修）、画风归属、战斗类型

**产出**:
- `specs/001-fight-scene-optimization/combat-index.md` — 完整索引表
- `specs/001-fight-scene-optimization/quality-matrix.md` — 初评矩阵

**验收**: 索引表覆盖全部 84 章（含"本章无战斗"标记），每场战斗有完整元数据

---

### Phase 2: 逐章回炉（US2）

**目标**: 所有战斗 ≥8/10 自查通过率，核心战斗 10/10

**分批策略**:
```
批次 1（重度, 预计 8-15 场）：完整重写
  → 卷三（029-043）BOSS战/首次遭遇污秽领主
  → 卷四（044-063）关键战斗
  → 卷五（064-080）镜面/梦境相关战斗

批次 2（中度, 预计 10-18 场）：局部修补
  → 卷一~二（001-028）早期战斗
  → 各卷中等质量战斗

批次 3（轻度, 预计 5-10 场）：微调
  → 过渡战、清杂兵、能力首秀（已达标项多）
```

**每场回炉流程**:
1. Read 战斗段落（含前后 2 句过渡）
2. 对照 10 项自查清单识别缺失项
3. Edit in-place：按 FR-004~FR-013 逐项修补
4. AI 自评：10 项逐项 ✓ 确认
5. 不达标 → 回到步骤 3（max 3 轮）
6. 达标 → Git commit（message 含自查分数 + 简要修改说明）
7. 例外 → commit message 注明原因

**每场战斗回炉检查点（AI 自评清单）**:
- [ ] 敌人辨识度：三步登场法？至少 2 项可识别特征？
- [ ] 阶段性：四段式/三层/三段（心理战）结构完整？
- [ ] 三要素：氛围~1/3 + 铺垫~1/3 + 动作~1/3？
- [ ] 多感官：至少 2 种激活？
- [ ] 视角切换：至少 1 次非主视角？
- [ ] 场景破坏：至少 1 处环境被波及？
- [ ] 画风一致：骑士线快/爽/笑？魔法少女线成长/拉扯/紧张？
- [ ] 记忆点：一句话能说清？
- [ ] 战后后果：伤痛/消耗/情绪 ≥1，与下章衔接？
- [ ] 格式合规：段落≤60字、无空行、对话无标签？

**产出**: 20-35 个 git commit，每个含自查分数

---

### Phase 3: 一致性修复（US3）

**目标**: 0 个 S1/S2 冲突

**步骤**:
1. 从回炉版本中提取每个角色的能力表现
2. 逐章比对：同一能力的范围/极限/代价是否一致
3. 从魔女图鉴 + 回炉版本中提取敌人耐受力数据
4. 建立敌人等级-耐受力对照表，校验同级一致
5. 校验魔法规则：影子属性边界、变身限制、圣器触发条件
6. 产出冲突报告（S1-S4 分级）
7. 修复 S1/S2 冲突（S3 容忍 ≤3 个）

**产出**:
- 更新 `novel/设定/角色/*.md` — 补充能力边界章节
- 更新 `novel/设定/世界观/魔女图鉴.md` — 补充等级-耐受力表
- 冲突报告（内嵌于最终优化报告）

---

### Phase 4: 双线画风区分度审查（US4）

**目标**: 所有战斗画风标签正确，骑士线/魔法少女线不混合

**步骤**:
1. 逐场确认 `style` 标签与角色功能定位一致
2. 骑士线检查：篇幅 300-800 字？节奏快？有笑点？终结技有定格感？
3. 魔法少女线检查：篇幅 500-1200 字？有来有回？魔法节奏链完整？有生死风险感？
4. 标记画风混合/模糊的战斗 → 确认 POV 角色 → 按 POV 归入对应画风
5. 检查交替节奏：是否有松紧带效应？

**产出**: 画风区分度审查结果（内嵌于最终优化报告）

---

### Phase 5: 终审与产出（US5）

**目标**: 生成最终优化报告 + 确认所有 SC 达标

**步骤**:
1. 汇总 combat-index.md 的 `checklist_score_after` → 计算平均分
2. 确认核心战斗全部 10/10
3. 确认例外 ≤ 15%
4. 确认 0 个 S1/S2 冲突
5. 生成优化报告：按卷统计、按类型统计、双线区分总评、一致性结果、3-5 个亮点案例
6. 输出读者抽样测试的 5 场推荐战斗列表

**产出**:
- `specs/001-fight-scene-optimization/optimization-report.md`

## Complexity Tracking

不适用——本计划无软件架构级别的复杂度违规。以下为写作特有的复杂性管理：

| 复杂性来源 | 管理策略 |
|-----------|---------|
| 84 章扫描上下文膨胀 | 5 个并行 agent，各负责 ~17 章，主线程仅做汇总 |
| 跨章能力一致性 | Phase 3 专门的一致性修复阶段 + 角色能力边界文档 |
| 回炉导致的新旧文风不一致 | 宽边界策略——战斗相关过渡文字可自由调整 |
| 战斗中同时出现骑士+魔法少女 | 以 POV 角色画风为准，允许一次视角切换对比 |

## 依赖关系

```
Phase 1 (扫描诊断) ──→ Phase 2 (逐章回炉) ──→ Phase 3 (一致性)
                         ↓                         ↓
                    Phase 4 (双线区分) ────────────→ Phase 5 (终审)
```

- Phase 2 依赖 Phase 1 的索引表+初评矩阵（需要知道哪些章节有战斗、优先级）
- Phase 3 和 Phase 4 依赖 Phase 2 完成（需要回炉后的版本）
- Phase 3 和 Phase 4 可并行
- Phase 5 依赖 Phase 3 + Phase 4 完成

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 某些战斗重写后自查仍不达标（3轮上限） | 中 | 低 | 标记为例外，确保 ≤15% |
| 回炉过程中发现新的战斗场景（扫描遗漏） | 低 | 低 | 扫描 agent 并行覆盖 + 主线程交叉校验 |
| 格式规则的约束限制战斗描写发挥 | 低 | 中 | 60字上限对于短句快攻足够，长句特写可拆为2-3句 |
| Git 提交过多导致历史噪音 | 中 | 低 | 合理——每章一个 commit 提供精确回滚粒度 |
